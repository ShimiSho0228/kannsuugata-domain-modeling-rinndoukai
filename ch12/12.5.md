## 12.5.1　選択型をテーブルにマッピング

選択型をマッピングするには以下の二つ
* すべてのケースを同じテーブルに格納
* 各ケースをそれぞれのテーブルに格納

#### 選択型とは

F#の機能で、以下の部分にあたる。
``ContactInfo``は ``EmailAddress``型も入るし、``PhoneNumber``型も可能


```` F#
and ContactInfo = 
    | Email of EmailAddress
    | Phone of PhoneNumber
````

Goは割愛

### 『すべてのケースを同じテーブルに格納』の実装

どっちの型を使用しているか判別できるフラグを持たせて、二つの型をまとめている。

```` sql
CREATE TABLE ContactInfo (
	ContactId int NOT NULL,
	IsEmail bit NOT NULL, -- ここが重要
    IsPhone bit NOT NULL, -- ここが重要
	EmailAddress NVARCHAR(100), 
	PhoneNumber NVARCHAR(25), 
	CONSTRAINT PK_ContactInfo PRIMARY KEY (ContactId)
)
````

### 『各ケースをそれぞれのテーブルに格納』の実装


『IDがどちらの型か示すテーブル』と
『型を定義するテーブル』をIDでつなげている。

複雑だが柔軟に対応可能  
e,g) EmailかPhoneのどちらかは必ず必須（NotNull）


```` sql

CREATE TABLE ContactInfo (
	ContactId int NOT NULL,
	IsEmail bit NOT NULL,
    IsPhone bit NOT NULL,
	CONSTRAINT PK_ContactInfo PRIMARY KEY (ContactId)
)

-- Email型の定義
CREATE TABLE ContactEmail (
	ContactId int NOT NULL,
	EmailAddress NVARCHAR(100) NOT NULL -- NOT NULL制約ができる
	CONSTRAINT PK_ContactInfo PRIMARY KEY (ContactId)
)

-- Phone型の定義
CREATE TABLE ContactPhone (
	ContactId int NOT NULL,
	PhoneNumber	NVARCHAR(25),  -- NOT NULL制約ができる
	CONSTRAINT PK_ContactPhone PRIMARY KEY (ContactId)
)

````

## 12.5.2 ネストした型をテーブルにマッピング

書籍でネストした型へのアドバイスとしては二つ

* 内部型が独自のアイデンティティをもつDDDエンティティの場合は、別のテーブルに格納
* 内部型がDDDの値オブジェクトで、独自のアイデンティを持たない場合は、親データに「インライン」で保存

OrderLineはエンティティなので、別テーブルにする

## 12.5.3 リレーショナルデータベースからの読み取り

ここからDB ⇒ コード。

### リレーショナルデータベースから読み取る実装

```` f#
open FShar.Data
[<Literal>]
// DB接続情報
let CompileTimeConnectionString = 
    @"Data Souce=(localdb)\MsSqlLocalDb; Initial Catalog=DomainModelExample;"

// SQL
type ReadOneCustomer = SqlCommandProvider<"""
    SELECT  * FROM CustomerId, Name, Birthdate
    FROM Customer
    WHERE CustomerId = @customerId
    """, CompileTimeConnectionString>
````

ReadOneCustomerから取得して構造体に入れる関数``toDomain``の実装

result式を使って実装　つまり、　**DBから取得したデータも信頼できないデータ**として扱う

```` f#
let toDomain (dbRecord:ReadOneCustomer.Record) : Result<Customer, _> =
    result { 
        // 型変換
        let! customerId = 
            dbRecord.CustomerId
            |> CustomerId.create
        let! name =
            dbRecord.Name
            |> String50.create "Name"
        let! birthdate =
            dbRecord.Birthdate
            |> Result.bindOption Birthdate.create

        // 構造体にして返却
        let customer = {
            CustomerId = customerId
            Name = name
            Birthdate = birthdate
        }
        return customer
    }
````

```` f#
let toDomain (dbRecord:ReadOneCustomer.Record) : Result<Customer, _> =
    result {

            |> CustomerId.create

            dbRecord.Birthdate
            |> Result.bindOption Birthdate.create // Null許容をさせている（後述）

            Name = name
            Birthdate = birthdate
        }
        return customer

````

上記コードはcreateのみでは出来ていなかったBirthdateのNull許容を実装するため、
ヘルパー関数を作成している

```` f#
let bindOption f xOpt =
    match xOpt with
    | Some x -> f x |> Result.map Some
    | None -> Ok None
````

もし、データベースに不正なデータが含まれることはないと確信できる場合（信頼できる場合）、  
panicとして扱ってよいため、エラーのResultを例外に変換する``panicOnError``を使用するようにコード変更が可能

```` f#
let toDomain (dbRecord:ReadOneCustomer.Record) : Customer = // Resultを消して
      
        let! customerId = 
            dbRecord.CustomerId
            |> CustomerId.create
            |> panicOnError "CustomerId" // 追加
        let! name =
            dbRecord.Name
            |> String50.create "Name"
            |> panicOnError "Name" // 追加
        let! birthdate =
            dbRecord.Birthdate
            |> Result.bindOption Birthdate.create
            |> panicOnError "Birthdate" // 追加

        {
            Customer = customerId
            Name = name
            Birthdate = birthdate
        }
````

panicOnErrorの実装は以下のようになります

```` f#
let panicOnError columnName result =
  match result with
  | Ok x -> x
  | Error err -> 
    let msg = sprintf "%s: %A" columnName err
    raise (DatabaseError msg)
````

このように``toDomain``関数を作成すると、DBを読み取りドメイン型として返す実装ができる。  
例として、以下の``readOneCustomer``関数の実装

#### Point

* データが見つからない場合：想定のエラー　⇒　Result.Errorとして扱う
* データが数件見つかる場合：想定外のエラー　⇒　panicとして扱う

このようにエラーを処理しているとNull等が想定されているかコードで明示できる

```` f#
let readOneCustomer (productionConnection:SqlConnection) (CustomerId customerId) =

  use cmd = new ReadOneCustomer(productionConnection)

  // コマンドを実行する
  let records = cmd.Execute(customerId = customerId) |> Seq.toList

  
  match records with
  // 件数0件
  | [] -> 
    let msg = sprintf "Not found. CustomerId=%A" customerId
    Error(MissingRecord msg)

  // 件数1件
  | [dbCustomer] ->
    |> dbCustomer
    |> toDomain // 【構造化】
    |> Result.mapError InvalidRecord

  // 件数2件以上
  | _ ->
    let msg = sprintf "Multiple records found for CustomerId=%A" customerId
    raise (DatabaseError msg)
````

すべてのものをパラメータ化する原則に従ってパラメータとして渡す``convertSingleDbRecord``を作成

```` F#
let convertSingleDbRecord tableName idValue records toDomain = // パラメータ化
    match records with
    // 件数0件
    | [] -> 
    let msg = sprintf "Not found. Table%s Id=%A" tableName idValue
    Error msg
    
    // 件数1件
    | [dbRecord] ->
        dbRecord
        |> toDomain
        |> Ok
    
    // 件数2件以上
    | _ ->
        let msg = sprintf "Multiple records found for Table%s Id=%A" tableName idValue
        raise (DatabaseError msg)
````

このジェネリックなヘルパー関数を使うことで、コードを数行にまとめることができる

```` f#
let readOneCustomer (productionConnection:SqlConnection) (customerId:CustomerId) =
    use cmd
    let tableName = "Customer"
    let records = cmd.Execute(customerId = customerId) |> Seq.toList
    convertSingleDbRecord tableName customerId records toDomain
````


## 12.5.4 リレーショナルデータベースから選択型を読み取る

クエリ型を定義

```` F#
type ReadOneContact = SqlCommandProvider<"""
SELECT ContactId, IsEmail, IsPhone, EmailAddress, PhoneNumber
FROM ContactInfo
WHERE ContactId = @contactId
""", CompileTimeConnectionString>
````

toDomain関数を作成

#### Point
IsEmailをのフラグを確認してContactInfoのどのケースを作成するか判定させる


```` f#
let toDomain (dbRecord:ReadOneContact.Record) : Result<Contact,_> = 
    result {
        let! contactId = 
        dbRecord.ContactId
        |> ContactId.create
    
        let! contactInfo =
        if dbRecord.IsEmail then // ここがメイン
            result {
                let! emailAddressString =
                    dbRecord.EmailAddress
                    |> Result.ofOption "Email expected to be non null"　// 少し追加（後述）
                let! emailAddress =
                    emailAddressString |> EmailAddress.create
                return (Email emailAddress)
            }
        else
            result {
                let! phoneNumberString =
                    dbRecord.PhoneNumber
                    |> Result.ofOption "Phone number expected to be non null"　// 少し追加（後述）
                let! phoneNumber =
                    phoneNumberString |> PhoneNumber.create
                return (Phone phoneNumber)
            }
        
        let contact = {
            ContactId = contactId
            Info = contactInfo
        }
        return contact
    }
````

EmailAddressはNull許容するので、OptionをResultに変換している

```` f#
module Result =
    let ofOption errorValue opt = 
        match opt with
        | Some v -> Ok v
        | None -> Error errorValue
````

先ほどの``convertSingleDbRecord``関数と組み合わせてコード行数を減らせる

```` f#
let readOneContact (productionConnection:SqlConnection) (ContactId contactId) =
    use cmd = new ReadOneContact(productionConnection)
    let tableName = "ContactInfo"
    let records =cmd.Execute(contactId =contactId) |> Seq.toList
    convertSingleDbRecord tableName contactId records toDomain
````

#### 終わり

テーブルごとにtoDomainを作るのは面倒ではあるが、以下理由で自力で書くべき
* ここは外部ツールではネストした選択型等複雑な処理ができない
* 機械的で分かりやすい


## 12.5.5 リレーショナルデータベースへの書き込み

ドメインオブジェクトをDTOに変換し、挿入、更新コマンドを実行

```` f#
type Db = SqlProgrammabilityProvider<CompileTimeConnectionString>

let writeConnect (productionConnection: SqlConnection) (contact:Contact) =

    // ドメインオブジェクトからプリミティブデータを抽出
    // 選択式の例
    let contactId = contact.ContactId |> ContactId.value
    let isEmail, isPhone, emailAddressOpt, phoneNumberOpt = 
        match contact.Info with
        | Email emailAddress ->
            let emailAddressString = emailAddress |> EmailAddress.value
            true, false, Some emailAddressString, None
        | Phone phoneNumber ->
            let phoneNumberString = phoneNumber |> PhoneNumber.value
            false, true, None, Some phoneNumberString


    // 新しい行を作成する
    let contactInfoTable = new Db.dbo.Tables.ContactInfo()
    let newRow = contactInfoTable.newRow()
    newRow.ContactId <- contactId 
    newRow.IsEmail <- isEmail
    newRow.IsPhone <- isPhone

    // データベースのNULLにオプション型を対応づける
    newRow.EmailAddress <- emailAddressOpt
    newRow.PhoneNumber <- phoneNumberOpt

    // テーブル追加
    contactInfoTable.Rows.Add newRow
    // データベース変更を加える
    let recordsAffected = contactInfoTable.Update(productionConnection)
    recordsAffected 
````
